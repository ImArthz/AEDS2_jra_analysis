\begin{abstract}
本ドキュメントでは、日本の競馬政府データ（2002年から2025年まで）の抽出、処理、および数学的グラフモデリングプロジェクトの深い技術的およびアーキテクチャの解剖を提示します。このレポートは、単なる結果の記述的提示を超え、JRA（日本中央競馬会）およびJBIS（ジャパン・ブラッドホース・インフォメーション・システム）ポータルに適用されたリバースソフトウェアエンジニアリングに深く踏み込みます。リレーショナルデータベースにおける構造的異常の処理（\texttt{ON UPDATE CASCADE}を介した委譲パラダイムを含む）、非線形データ構造の実装、Webスクレイピング中に直面したネットワークの課題（IPブロックやレガシーHTML4ページでのHTMLパーサーの不一致など）、および\textit{PageRank}、固有ベクトル中心性、遺伝的ツリーアルゴリズムの基礎となる数学について幅広く議論します。このドキュメントは、リポジトリに含まれる実装のシニアレベルのソフトウェアエンジニアリングリファレンスとして機能します。
\end{abstract}

\section{ドメインの紹介と動機}
現代の競馬のコンテキストは、本質的に非同期データによって駆動される厳密に定量的なエコシステムです。動物の遺伝的負荷（5代血統）、イベント当日の気象条件、馬場状態（芝、ダート、良馬場など）、および騎手、調教師、アスリート間に確立された歴史的シナジーなどの孤立した要因が、複雑で高度に非線形な因果関係の網を形成します。高度なデータ構造2（AEDS 2）コースのために考案されたこのプロジェクトの主な学術的目的は、この現実世界の複雑さを捉えて抽象化し、構造化されていないWebフォーマットから強く型付けされたリレーショナル行列に変換し、その後、動的な競争と系譜のグラフでモデリングすることでした。

計算力と分析力を、世界のエリートクラスのレース、特に\textit{Japan Racing Association}（JRA）の管轄下にある重賞レース（G1、G2、G3）のみに集中させることを選択しました。この制限の根底には純粋な数学的決定がありました。もし\textit{パイプライン}が下位クラスのレース（未勝利や条件戦）を含んでいた場合、結果として得られるデータベースは、勝利と敗北が主に統計的なランダム性（\textit{White Noise}）に由来する数千の下位および中位のアスリートで膨れ上がっていたでしょう。

ピラミッドの頂点（重賞レース）のみをフィルタリングすることで、技術的な品質が極めて高いデータセットの生成を保証し、世代を超えた特性の遺伝的伝達を観察するための制御された非常に豊かな環境を提供します。この（JRAから抽出された）運動能力と（JBISから抽出された）遺伝的背景の共生的なペアリングは、人工知能、隠れマルコフ連鎖、さらには実際の属性と遺伝的親交配アルゴリズムによって手続き的に供給されるトレーディングカードゲームのコアアルゴリズムの学術的生成提案における将来の予測モデリングのための堅牢な道を間違いなく切り開きます。

\section{厳密なデータベースアーキテクチャとモデリング}
構築されたエコシステム全体のバックボーンはデータベースです。トランザクション\textit{エンジン}として\texttt{SQLite3}を利用しました。これは、ローカルでの分離、バックグラウンドサービスの\textit{デーモン}からの独立性、および増分\textit{チェックポイント}プロセス中の高速なI/O操作の生来のサポートのために意図的に選択されました。

\subsection{論理モデルとエンティティ関係（ER）モデル}
データベースの\textit{設計}は、冗長性を減らし機能的依存性を分離するために、第3正規形（3NF）に従いました。ベースとなるリレーショナルモデルは、4つの中心的なエンティティで構成されています：
\begin{enumerate}
    \item \textbf{\texttt{races}テーブル（中心的なイベントエンティティ）:}
    レースが展開されたコンテキストメタデータを保存します。主要な属性には、複合ハッシュ識別子\texttt{race\_id}、\texttt{date}、空間メトリック\texttt{distance}、時間的要因\texttt{weather}、および馬場摩擦\texttt{going}が含まれます。
    \item \textbf{\texttt{race\_entries}テーブル（ファクトテーブル / \textit{多対多}の関係）:}
    レコード密度の点で最も重要なテーブル。その正確なイベントでの各動物の個別の運動能力メトリックを記録します。ミリ秒単位の走破タイム、体重、課せられたハンディキャップ重量、最終コーナーでの通過位置のベクトル、物理的な着差、および\textit{オッズ}（配当確率）などの属性が含まれます。このテーブルは、\texttt{races}と\texttt{horses}にリンクされた外部キーに密接に依存しています。
    \item \textbf{\texttt{horses}テーブル（マスターアスリートエンティティ）:}
    時間を超えた統合定数エンティティ。公式の\texttt{horse\_id}主キー、数百万円に上る累積獲得賞金額、性別、正確な生年月日、および物理的な毛色を保存します。
    \item \textbf{\texttt{pedigree}テーブル（階層的再帰関係）:}
    遺伝的ブリッジ（馬Aと親として機能する馬BおよびCをリンクするID）を保存します。
\end{enumerate}

\subsection{制限となる外部キーのアーキテクチャ上のジレンマ（外部キークラッシュ）}
このデータエンジニアリングプロジェクトで直面した最大の開発のボトルネックの1つは、\textit{スクレイピング}自体からではなく、時間的に交差するリレーショナルアーキテクチャから生じました。
カスケード実行フロー中、JRAエクストラクタは常に\textit{パイプライン}で最初に開始されます。レースと馬の名前を\textit{漢字/カタカナ}文字で正常にキャプチャします。ただし、JRAは古い結果では、その後の生物学サイト（JBIS）で使用されるグローバルな英数字の識別子を提供していません。

リレーショナルモデルが第3正規形を崩さないようにし、\texttt{race\_entries}に孤立したレコードが生成されるのを防ぐために、\texttt{horses}テーブルに識別子が必要でした。最初の解決策は、日本語の名前自体を暫定的なPK（主キー）として使用することでした。\texttt{race\_entries}テーブルはそれをそのまま前提としていました。

参照整合性の崩壊は、ステージ2（JBISモジュール）で必然的に発生しました。抽出ロボットが生物学的プロフィールに到達し、一意の生物学的識別\textit{ハッシュ}（例：\texttt{0000331006}）を持つクリーンなURLをキャプチャすると、システムは\texttt{horses}テーブルに対して\texttt{UPDATE} SQLコマンドを発行し、日本語の名前をクリーンな数値キーで上書きしようとしました。直ちに、SQLite\textit{エンジン}は重大な例外を発生させました：
\texttt{sqlite3.IntegrityError: FOREIGN KEY constraint failed}。
子レコードにリンクされているPKを変更することは、標準のSQL制限の法則に違反していました。

\subsection{解決策：ON UPDATE CASCADE パラダイム}
数十万のセルをループして子レコードを同期的に更新する手続き型\textit{スクリプト}を作成する時間的コスト$O(N)$を被ることなく、この脆弱性を軽減するために、DBMSへの直接委譲の理論に頼りました。厳密な\texttt{ON UPDATE CASCADE} DDL制約を注入することにより、データベース初期化の\textit{スキーマ}を構造的に変更しました。

\begin{lstlisting}[language=SQL, caption=カスケード伝播によるrace\_entriesテーブルの高度なモデリング]
CREATE TABLE IF NOT EXISTS race_entries (
    race_id TEXT,
    horse_name TEXT,
    horse_id TEXT,
    position INTEGER,
    finish_time TEXT,
    -- ... (レポートの簡潔さのために省略) ...
    margin TEXT,
    PRIMARY KEY (race_id, horse_id),
    FOREIGN KEY (race_id) REFERENCES races (race_id),
    FOREIGN KEY (horse_id) REFERENCES horses (horse_id) ON UPDATE CASCADE
);
\end{lstlisting}

このシンプルでありながら深遠な\textit{制約}の数学的変更により、ロボットが40以上の登録レースを持つ有名な馬の主キーを変更する\texttt{UPDATE}を実行すると、SQLiteは、Bツリーの最適化された内部アルゴリズムを採用して、子テーブルをトラバースし、40すべての二次キーを完全に非同期、不可視、かつアトミックに安全に書き換えます。このアーキテクチャ上の決定は、実行ライフサイクルにおける数十時間のリファクタリングを節約し、不可逆的な\textit{チェックポイント}の損失を防ぎました。

\section{自動データ抽出エンジニアリング（Webスクレイピング）}
古い政府ポータルからの大規模な自動データ抽出は、巨大な標準化の課題を呼び起こし、\textit{パーサー}内で偏執的な程度の回復力と例外処理（Try/Catch）を必要とします。

\subsection{JRAスクレイパーモジュール：レガシーとセマンティックHTMLの地獄}
\textit{Japan Racing Association}の歴史的な重賞レースデータベース（アクセス可能な記録は2002年まで忠実に遡ります）は、Webセマンティクスが事実上存在しなかった時代に設計されました。現代のWeb（HTML5）では、\textit{タグ}は通常、簡単にキャプチャできるセマンティッククラス（例：\texttt{<td class="horse-weight">498</td>}）を持っています。
2000年代のJRAのレガシーコードでは、情報はCSS識別子のない\textit{ネストされたテーブル}内に構造化されており、美学と構造はインライン属性と厳格な階層を介して生成され、分析された年によっても変化しました（2005年の\textit{レイアウト}は2020年の\textit{レイアウト}とは異なります）。

\textbf{ハイブリッド変数の問題（属性の汚染）:} JRAの元のソースコードは、異なる指標を分離していませんでした。たとえば、「馬体重」を意図した列は、フォーマットの異なる2つの重要なデータポイントを同じテーブルのセルにマージしていました：当日の基本体重と前回のレースからのパラメータの変動（例：\texttt{498(+2)}、あるいは\texttt{498(--4)}のような奇妙なフォーマットやマークなしなど）。
将来の教師あり\textit{機械学習}アルゴリズムの純度を確保するために、この融合は統計的に有害であり容認できません。
\textbf{採用された解決策（正規表現による抽出）:} \textit{BeautifulSoup}解析ツリーの子ノードを再帰的に反復し、ベクトルを論理的に分割する堅牢な正規表現エンジンをPythonで実装しました。悪意のあるダブルダッシュ文字を実際の符号付き負の数に変換することに加えて、DTO（\textit{データ転送オブジェクト}）内の指標を\texttt{weight\_base = 498}と\texttt{weight\_variation = 2}に厳密に分割します。

\textbf{漸近的最適化（スキップロジック）:} 各スクレイプは、非常に高いレイテンシ定数（Ping）を持つネットワーク上で$O(1)$のコストがかかるため、\texttt{SELECT 1}スキャンを介して、レースの一意の識別\textit{ハッシュ}がSQLiteデータベースインデックスツリーにすでに存在するかどうかをテストするフィルタリングレイヤーを挿入しました。スクリプトの再実行におけるパフォーマンスの向上は垂直に上昇しました。

\subsection{JBISスクレイパーモジュール：定義リスト vs. 従来のテーブル}
\textbf{セマンティックの異常（有名な絶対零度のバグ）:} プロフィールを正常にスクレイピングした後の後処理の検証中に、データベースには、100％のエリートアスリートが\texttt{0円}に相当する生涯の金銭的収益指標（\textit{Lifetime Earnings}）を保持していることが示され、生年月日情報の保持にも失敗していることが指摘されました。
実際の日本のページのDOMをリバースエンジニアリングし、\textit{ペイロード}パケットをトレースする必要がありました。従来のWebの99％とは異なり、JBISの生物学ポータルは、表形式のプロフィールを形成するために\textbf{\texttt{<table>}要素}とその子（\texttt{<th>}と\texttt{<td>}）を使用していないことがすぐに特定されました。代わりに、日本のチームはセマンティックな定義リスト（用語の\texttt{<dt>}と説明的な詳細の\texttt{<dd>}）を採用していました。Pythonの\textit{パーサー}が執拗にテーブルの\textit{タグ}を狩ったため、グローバルに\textit{Null}を返しました。

Pythonアーキテクチャに課された修正は、リストの兄弟ノード（\textit{Sibling Nodes}）の反復をインスタンス化することでした。

\begin{lstlisting}[language=Python, caption=JBISにおける動的修正と兄弟走査]
# リファクタリング: 定義リスト（ヘッダーdt、値dd）の最適化された検索
for dt in soup.find_all("dt"):
    label = dt.get_text(strip=True)
    
    # ポイント: 直後のDOMの兄弟を見つける。
    dd = dt.find_next_sibling("dd")
    if not dd: continue
    val = dd.get_text(strip=True)
    
    if "総賞金" in label: # 日本語での"Total Earnings"文字列 (Shift-JIS/UTF8)
        # 偽装された小数点の変動に対する正規表現による厳しいクリーニング。
        m = re.search(r'([\d,]+(?:\.\d+)?)', val)
        if m:
            num_str = m.group(1).replace(",", "")
            # ネイティブシステムは「万円」（X.X * 10,000）で記録します。 
            profile["total_earnings"] = int(float(num_str) * 10000)
\end{lstlisting}

\subsection{サーバーの過負荷とブロックアルゴリズム（エクスポネンシャルバックオフ）}
\textbf{避けられないサイバー防衛の問題:} 主に日本のローカルトラフィックに割り当てられているサーバーから、8,000頭の馬と33,000のプロフィールのレポートを抽出することは、厳しいブロックロジックを引き起こしました。悲劇的なコード403（Forbidden）と深刻な\textit{ソケット}タイムアウトを伴うHTTPリターンは、処理中（約48時間続いた）の\textit{パイプライン}の完全な破壊を脅かしました。
\textbf{ネットワークアーキテクチャに基づくソリューション（TCP）:} 発生した各\textit{リクエスト}の前後に、厳密な2.0秒の延期不可能な\textit{Politeness Delay}（\textit{Cronjob Sleep}）を注入し、PPS（\textit{Ping-Per-Second}）を許容レベルまで減らしました。さらに、\textit{エクスポネンシャルバックオフ}輻輳制御アルゴリズムを実装しました。パケットが拒否されたり、アジアのルーターの時間制限に達したりした場合、アプリケーションは\textit{クラッシュ}を吸収し、許可が得られるまで乗数的に増加する一時停止をスケジュールして、\textit{無限ループ}やセッションの進行の早すぎる損失を防ぎます。

\section{深い再帰の生物学的アルゴリズム：血統DFS}
メンデルの遺伝的血統を破棄した場合、動物の競技生物学における有効な予測評価は存在しません。
エンジンは、5つの純粋な世代に後退する絶対的な階層ツリー（家系図）という残酷なベクトルをキャプチャするように設計されました。このために、スクリプトは古典的なデータ構造アルゴリズムである\textit{再帰的深さ優先探索}（DFS）を実行します。

\texttt{rowspan}属性によって密に結合されたテーブルのメッシュをナビゲートすることで、Pythonは数学的な分岐を完全に推論します。各馬$C_{root}$をレベル$L_0$と見なす場合、父親の世代は$L_1$（2ノード）、祖父母は$L_2$（4ノード）、曾祖父母は$L_3$（8ノード）というようになります。全体として、遡及的な第5世代は、分析された動物の頂点に一意に接続された信じられないほどの$2^1 + 2^2 + 2^3 + 2^4 + 2^5 = 62$個の異なる頂点の追跡とインデックス付けを要求します。情報の量は非常に驚異的であり、これらの頂点は純度計算のための橋渡しをします。

\section{データクレンジングとセマンティック翻訳（ハッシュ辞書）}
分析前のパイプラインの最後のフロンティアは、鋭い処理に基づいています。
システムは、人間の忠実なチェックのための生の日本語フォーマット（オリジナル）でピボットテーブルを生成し、並行して標準化された翻訳済み行列を生成します。なぜか？\textit{Garbage-In, Garbage-Out}（ゴミを入れればゴミが出る）のためです。エキゾチックな\textit{Shift-JIS}（\texttt{cp932}）文字列を将来の予測および分類\textit{Scikit-Learn}ニューラルネットワークに渡すと、辞書変換ベクトルのバイアスは壊滅的なものになります。

\begin{lstlisting}[language=Python, caption=翻訳と変換のO(1)行列の静的辞書]
TRACK_CONDITION_MAP = {
    "良": "Firm",             # 完璧に乾いたトラック
    "稍重": "Good to Soft",   # やや水浸し
    "重": "Soft",             # 完全に濡れている (Yielding)
    "不良": "Heavy"           # 純粋な泥
}

WEATHER_MAP = {

\end{lstlisting}

これらのマッピングは、$O(1)$のアクセス複雑性の構造を利用して、反復的な計算の途切れなしに\textit{文字列}を完全に置き換えます。結果として得られる\textit{英語フォーマット}のベースは、グローバルレベルのプロジェクトの相互運用性を保証します。

\section{数学的モデリングとグラフ理論 (AEDS 2)}
このセクションは、このすべてのデータベースエンジニアリングの主要かつ寛大な目的を奉献します。線形レコード（テーブルとスプレッドシート）を解体し、地理的行列とリンクされたメッシュとして情報的視点を再配置すると、強力なグラフ（$G=(V, E)$）が生成され、学術分野で教えられ必要とされるアルゴリズムへの道が開かれます。

\subsection{系譜における有向非巡回グラフ (DAG)}
救出された祖先を正式な\textit{有向非巡回グラフ}（$DAG$）フォーマットにモデル化しました。この特殊な厳密なグラフタイプでは、論理的なトポロジカルサイクルは存在せず、すべてのエッジは一方的に終わりに向かって流れます。
ここで、頂点の集合$V$は歴史的な馬です。各エッジ$e_{1}=(u, v)$は流れを方向付け、$u$が$v$を産んだ（または生成した）という不変の事実を象徴しています。ループ（$u \to v \to u$）が発生することは生物学的に不可能であり、これが非巡回性を封じ込めます。

\textbf{実際のアルゴリズムへの影響（LCA）:} 世界のエリートスポーツの血統の最大の悪役の1つは、非常に高い近親交配率（曾祖父母や兄弟の血を共有する動物間の交配であり、慢性的な肺や身体の病気や制限を引き起こす）であるため、Pythonライブラリ（\texttt{NetworkX}など）を利用して$O(V+E)$で\textit{最小共通祖先}を処理します。
生成ゲームで「交配」しようとしている2つの馬の頂点が与えられた場合、ツリートポロジーは両方が共有する最も近い祖父ノードを正確に検索して明らかにし、数分の一秒でそれらの間の分数的なメンデル距離を計算します。

\subsection{競争ネットワーク：マトリックスとPageRankパラダイム}
おそらく、従来の線形統計スプレッドシートに対するこの作業の最も大胆な知的進歩は、エリートアスリートの品質評価モデルです。
従来、マスコミは線形の金銭的計算（総獲得賞金や1着の絶対数）を盲目的に観察することによって、動物を伝説として分類しています。グラフ理論の領域では、この線形メトリックが論理的な欠陥と認知バイアスを抱えていることがわかっています（動物は、ひどいレベルの動物や中流階級の動物を順次打ち負かし、スポーツのアイドルを卑怯に避けるだけで、世界1位にランク付けされる可能性があります）。

\textbf{二部中心性と名声のネットワークの理論}を注入することで、このパラダイムを解決しました。スポーツ環境を競争グラフとしてモデル化しました。馬Aが馬Bより先にフィニッシュラインを越えた場合、重み付けされた有向エッジ$B \to A$が生成されます（BはAに敬意/権威を「寄付」します）。私たちは、この残忍で複雑なマトリックスを、Larry Page（有名な\textit{Google PageRank}）によって考案されたまさに億万長者の数学的並べ替えおよびインデックス作成アルゴリズムにかけます。

スポーツ生物学に適応されたPageRank方程式は次のように確立されます：
\[ PR(A) = (1-d) + d \sum_{B \in M(A)} \frac{PR(B)}{C(B)} \]
ここで：
\begin{itemize}
    \item $PR(A)$は、馬$A$の真の潜在的な運動能力です。
    \item $d$は確率的分散係数です（標準の数学的減衰として$0.85$を想定します）。
    \item $M(A)$は、$A$によってひどく打ち負かされ屈辱を与えられた、つまりアクティブなエッジが$A$に流れている、制限された頂点$B$の集合を指します。
    \item $C(B)$は、敗北した馬$B$の総アウトバウンドエッジの分岐を反映しています。
\end{itemize}

このアプローチの素晴らしさと疑いのない成功は、出力結果で視覚化されます。JRAでのキャリアでごくわずかなレースにしか参加せず、生涯で一度も1着になったことがない（SQLおよびCSVテーブルでは、失敗と見なされ、ランキングの底辺である30,000位に残される）という弱者の馬が、非常に高い$PR$と*固有ベクトル中心性*を持つ真に伝説的で神話的な馬の尻尾の背後にあるファネルを通過して、繰り返し2着と3着に到達した場合、アルゴリズムは流れ、これらの巨大で密な頂点の権威を反射によって間接的に吸収します。弱者は、勝利がゼロであっても、システムテーブルの\textit{PageRank}のトップにランクされ、アルゴリズムは、この馬が身体的に並外れており、スポーツの不屈の伝説と年代順に同じ時代に生まれたというひどい不運のためだけに金を欠いていたことを数学的に証明します。グラフは才能の仮面を剥ぎ取り、「データ形式のダイヤモンド」を抽出します。

\section{最終的な考慮事項と将来のAIの拡張}
このアーキテクチャの実用的かつ分析的な開発は、計算構造の古典的な概念を、2000年代のレガシーインターネットに由来するノイズに満ちた、混沌として断片化されたドメインの厳しい抽出と結びつける緊急の必要性を明白に証明しました。
統合された結果は、QAによって検証された3万3000以上のスポーツエントリと、セマンティックグラフで個別にマッピングされた8000のノードを上回りました。
このような非常に肥沃な基盤により、私たちはプログラムの次の進化のための強固な基盤を築きました。英語で標準化されたこの3次元マトリックスを、ディープニューラルネットワーク（\textit{ディープラーニング}）および分類処理モデルによって完全に吸収し、実際の対戦を予測するか、大学でのインテリジェントトレーディングカード（TCG）の統計的な数学的および手続き的開発ベース（\textit{手続き型ゲームデザイン}）として機能させます。
